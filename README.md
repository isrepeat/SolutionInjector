# SolutionInjector

Существующий механизм вставки решения, модель `SolutionStructure` и парсеры сохранены. Анализ зависимостей и очистка добавлены отдельными модулями `Dependencies`, `Operations`, `Cli`, `Helpers` и `IO`.

## Анализ и очистка

```cmd
SolutionInjector.exe analyze "C:\Projects\Application\Application.sln" --scope UniversalDevKit --json
SolutionInjector.exe prune "C:\Projects\Application\Application.sln" --scope UniversalDevKit
SolutionInjector.exe prune "C:\Projects\Application\Application.sln" --scope UniversalDevKit --apply
```

`--scope` задаёт имя или GUID папки решения, внутри которой разрешено удалять проекты. Одноимённые папки нужно различать по GUID. Все проекты вне этой папки считаются корнями: их прямые и транзитивные зависимости сохраняются. Дополнительные корни внутри папки задаются повторяемым `--root <имя или GUID>`.

Без `--apply` решение не изменяется. При применении удаляются недостижимые проекты и опустевшие папки выбранной области; файлы проектов и исходников остаются на диске. Перед заменой проверяется, что прочитанные файлы не изменились, и создаётся резервная копия решения. Повторная очистка без новых изменений не переписывает решение.

Анализ учитывает XML `ProjectReference`, локальные `Import`, ближайшие `Directory.Build.props/targets`, `SharedMSBuildProjectFiles` и `ProjectDependencies`. Условные зависимости объединяются, чтобы сохранить проекты, нужные другим конфигурациям. Поддерживаются пути с `MSBuildThisFileDirectory`, `MSBuildProjectDirectory` и `SolutionDir`; стандартные импорты toolchain пропускаются.

Это структурный анализ, а не полное выполнение MSBuild. Неизвестные свойства в путях, отсутствующие локальные файлы, повреждённые зависимости и другие неоднозначности блокируют применение. В JSON возвращаются `blocked`, `applied`, списки удаления, рёбра зависимостей и `issues`. Код завершения: `0` — успех, `1` — ошибка выполнения, `2` — очистка заблокирована.

Для Disconnect предполагается следующий порядок: удалить импорт выбранного компонента из consumer, выполнить предварительный анализ, затем применить очистку области UniversalDevKit. Автоматический вызов из Connect/Disconnect в эти изменения не входит.

## Проверки

```powershell
MSBuild Tests\CleanupTests.vcxproj /p:Configuration=Release /p:Platform=x64
& .\Tests\Run.ps1 -Executable .\!artifacts\tests\bin\CleanupTests.exe
```

Тестовый исполняемый файл использует производственные анализатор, планировщик, модель и парсеры; исключает несвязанные графические модули старого UtilityHelpersLib. Проверяются несколько потребителей, отключение последнего, зависимости решения, дополнительные корни, сохранение неизвестных секций, блокировка неоднозначного анализа и повторное применение.

Основной проект сохраняет зависимость от UtilityHelpersLib и toolset v142. В установленном окружении с v145 полная сборка также требует устранения существующих ошибок в старом submodule (Conversion.h и TextureDesc.cpp); submodule в этих изменениях не обновлялся.
